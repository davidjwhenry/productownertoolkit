# Personal

This folder is for lightweight personal working notes that support your product practice without becoming part of the canonical team or requirements context.

## Purpose

Use this space for rough notes, reminders, and personal tracking that help you think and operate.

To-dos may be created or updated by other skills, but this folder should stay simple and easy to scan.

## Suggested Structure

- `notes/` for lightweight personal notes, reminders, and rough thinking
- `to-dos/not-done/` for active to-dos
- `to-dos/done/` for completed or archived to-dos you want to keep for reference

## Naming

Use simple sequential note names:

- `001.md`
- `002.md`
- `003.md`

If helpful, add a short slug after the number:

- `001-weekly-ops-notes.md`
- `002-stakeholder-follow-ups.md`

Meeting notes are the main exception. For notes created from a dated meeting, prefer:

- `2026-04-12-q2-planning.md`
- `2026-04-12-stakeholder-sync.md`

## Rules

- Keep these notes personal and lightweight.
- Do not store canonical company, team, or requirements context here.
- Move finished items from `to-dos/not-done/` to `to-dos/done/` rather than deleting them if you want a record.
- If a note becomes important shared context, promote it into the right folder instead of leaving it here.
